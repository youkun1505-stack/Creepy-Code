# チームの長期記憶（.agent-memory）

チームで決まったことや確かめた知識を、次の作業・別のメンバー・別の AI（Claude Code・Codex）でも使えるように残す場所です。
Git で共有します。作業のあいだだけ使う一時ファイル（`.ai-tmp/`）とは別です。

記録の一次情報は、いつもリポジトリのコード・資料・Git の履歴です。ここの記録はそれを置き換えません。
記録と今のコードや公式の説明が食い違うときは、今のほうを信じ、記録を直します。

## 分け方

| フォルダ | 残すもの | 例 |
| --- | --- | --- |
| `decisions/` | チームで決まったこと（コードや履歴だけでは分からない決定） | DB に何を使うか、担当の分け方、使う AI サービス |
| `knowledge/` | 確かめた事実・仕組み・エラーの解き方 | Supabase に接続するときの注意、よく出るエラーと直し方 |
| `procedures/` | 何度も使う手順 | ローカルで動かす手順、テストデータの入れ方 |

一覧は `index.md` です。記録を足したり直したりしたら、同じ変更で `index.md` も更新します。

## 残してよいもの・いけないもの

残してよいもの：

- 根拠（ファイル名・コミット・PR・公式の説明の URL・メンバーの決定と日付）を書ける内容
- チームの何人かに関わる内容

残してはいけないもの：

- API キー・パスワード・接続文字列・トークンなどの秘密情報（環境変数の名前だけなら可）
- 個人情報、会話の写し
- 作業メモ（`task.md`）・チケット（`T-1.md`）・引き継ぎ記録（`handoff.md`）の中身
- 根拠のない推測、確かめていない環境の話
- コード・資料・`AGENTS.md` を読めば分かること
- 自分だけに関わる学び（それは各 AI の個人のメモリに残す）

## 書く人と書くとき

- メンバーが「チームの記憶に残して」と頼んだとき、またはメンバーが残すと決めたときに書く。
- Claude Code では記録係（`memory-manager`）が書く。Codex など記録係がいない道具では、メンバーの「はい」をもらって司会役が書く。
- 同じ内容の記録があれば、新しく作らずにその記録を直す。

## 書き方

ファイル名は英数字とハイフン（例：`decisions/db-supabase.md`）。中身は次の形にします。

```
# 〇〇（題名）
- 種類：決定 ／ 知識 ／ 手順
- 決めた日・確かめた日：YYYY-MM-DD
- 確かさ：高 ／ 中 ／ 低（理由を一言）
- 当てはまる場面：（どの作業・どの機能で使うか）
- 根拠：（ファイル名・コミット・PR・URL・誰がいつ決めたか）

## 中身
（決まったこと・確かめたこと・手順を短く）

## 確かめられていないこと
（なければ「なし」）

## 直した記録
- なし（直したときは、日付・理由・根拠を書く。元の内容を黙って消さない）
```

## 使い方

- 作業を始めるときは `index.md` を見て、関係する記録だけを読む。全部は読まない。
- 変わりやすい内容（外部サービスの仕様など）は、使う前にもう一度確かめる。
- 確かさが「低」の記録は、決まったこととして扱わない。
