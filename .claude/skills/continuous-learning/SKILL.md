# continuous-learning（セッションの学びをメモリに残す）

セッションで得た学びをメモリに残し、次のセッションで同じ説明や同じ失敗を繰り返さないようにする。保存先は Claude Code の自動メモリ（`~/.claude/projects/<プロジェクト>/memory/`）で、書き方はシステムプロンプトにあるメモリのルールに従う。

## 手順

### 1. 振り返る

今のセッションの会話を最初から見直し、次の5種類の学びを探す。

| 種類 | 探すもの | メモリの type |
|---|---|---|
| 訂正 | ユーザーに直された、止められた、「そうじゃなくて」と言われたこと。逆に「それでいい」と認められた進め方 | `feedback` |
| エラーの解き方 | 時間がかかったエラーと、最終的に効いた直し方 | `project` または `feedback` |
| 繰り返した作業 | このセッションで2回以上、同じ手順を踏んだ作業 | `feedback`（手順が長ければスキル化の候補として報告） |
| 決まった方針 | 技術の選定、担当範囲、締切など、コードやgit履歴からは読み取れない決定 | `project` |
| ユーザーについて | 役割、得意なこと、好み | `user` |

次のものは残さない。

- 打ち間違いの修正など、その場限りのこと
- コード・git履歴・AGENTS.md・CLAUDE.md を見ればわかること
- 外部サービスの一時的な障害
- パスワード、APIキー、接続文字列などの秘密情報（場所や変数名だけなら可）

### 2. 既存のメモリと照らし合わせる

`MEMORY.md` と関係しそうなメモリファイルを読み、取り出した学びごとに次のどれかに分ける。

- **新規**：まだどこにも書かれていない
- **更新**：既にあるメモリの内容を足す・直す
- **再発**：既にあるメモリ（特に `feedback`）と同じ指摘を、またユーザーから受けた
- **削除**：今回の会話で、間違いだとわかったメモリ

### 3. ユーザーに確認する

保存する前に、次の形で一覧を見せて、どれを保存するか聞く。ユーザーが選んだものだけを保存する。

```
今回のセッションから、次の学びを取り出しました。

1. [新規・feedback] （学びの一文）
   根拠：（会話のどの場面か）
2. [再発・feedback] （既存メモリ名）… 今回で3回目
...
```

### 4. 保存する

- 新規：メモリファイルを1つ作り、`MEMORY.md` に1行の目次を足す。
- 更新：既存のファイルを書き換える。新しいファイルは作らない。
- 削除：ファイルを消し、`MEMORY.md` の行も消す。
- 再発：既存ファイルの本文にある `**回数:** n` を1つ増やす（無ければ `**回数:** 2` を足す）。あわせて `**直近:** YYYY-MM-DD` を今日の日付にする。

`feedback` と `project` には、システムプロンプトのルールどおり `**Why:**` と `**How to apply:**` の行を付ける。「明日」「来週」などの相対的な日付は、具体的な日付に直して書く。

### 5. 強制力を上げるか判断する

保存した結果、`**回数:**` が3以上になったメモリがあれば、そのことをユーザーに伝える。そして、`harness-optimizer` エージェントでルールの強制力を一段上げる案（例：手順に組み込む、フックで自動チェックする）を出すかどうか聞く。メモリに書いておくだけでは、守られていないためです。

### 6. 報告する

最後に、保存・更新・削除したメモリのファイル名と、それぞれの理由を短く報告する。
