## P-01 の画面の詳細（実装に合わせた補足）

設計書本文には要点だけを書いています。ハリボテ（`bridal-app` の `TopController.java`・`common/top.html`・`css/top.css`）で作った内容は次のとおりです。

### 画面構成（PC 基準・3列）

| 列 | 未ログイン | ログイン後（顧客） |
|---|---|---|
| 左 | 今の流行（中身は検討中。いまは「準備中」の枠だけ。枠の中だけスクロール） | 同じ |
| 中央 | サービスの説明／ご利用の流れ（4ステップ） | 次にやること／進み具合（5段階） |
| 右 | 会員登録・ログインのボタン／ページ内リンク（スクロールしても付いてくる） | 各画面へのメニュー（押せない項目は理由を表示） |

タブレット・スマホでは1列に並べ替えます（未ログイン：メニュー → 本文 → 今の流行／ログイン後：本文 → メニュー → 今の流行）。

### ログイン後の状態ごとの表示

| 状態 | 次にやること（ボタン） | 進み具合の「いまここ」 | マイプラン・料金 | プランナーとのチャット |
|---|---|---|---|---|
| かんたん質問がまだ | まずはかんたんな質問に答えてみましょう（はじめる） | かんたん質問 | 押せない：AIがプランを作ると見られます | 押せない：マイプランで「プランナーに相談する」を選ぶと使えます |
| かんたん質問の途中 | かんたん質問の続きから（続きをはじめる） | かんたん質問 | 押せない（同上） | 押せない（同上） |
| プラン作成済み・相談前 | AIのプランを確かめましょう（マイプランを見る） | 担当プランナー決定 | 押せる | 押せない（同上） |
| 担当を決めている | 担当プランナーを決めています（料金シミュレーションを開く） | 担当プランナー決定 | 押せる | 押せない：担当プランナーを決めています。決まるとここから相談できます |
| 担当が決まった | 担当プランナーが決まりました（プランナーとチャットする） | 合意 | 押せる | 押せる |

「AIに相談する」（P-10）は、どの状態でも押せます。

### ハリボテ用の仮の仕組み

- ログイン機能がまだ無いので、ログイン後の表示は仮の URL `/after-login-tmp` で確認します。末尾の `?state=` で状態を切り替えます（`new`（初期値）／`hearing`／`plan`／`assigning`／`assigned`）。
- 本番では URL で切り替えず、ログイン中の顧客のデータから状態を決めます。ログイン機能ができたら `/after-login-tmp` は削除します。
- 会員名は、テストデータの顧客「テスト 顧客」を仮に表示しています（本番は USERS.NAME）。
- まだ無い画面への行き先は仮の URL です（`/auth/register`・`/auth/login`・`/hearing/step1`・`/hearing/step2`・`/plan/myplan`・`/plan/simulation`・`/chat`）。
- ログアウトは、ログイン機能ができるまで、押すとトップ（`/`）に戻るリンクにしています（`POST /logout` を受ける先がまだ無いため）。ログイン機能ができたら POST のフォームに戻します。

## 10/20 に決めた仕様変更（PR #23 のレビューを受けて）

設計書（docx）にはまだ書いていません。仕様変更は最後にまとめて設計書に書き込む方針なので、決まった内容をここに記録しておきます。

### 1. AI深掘り質問（P-10）を、かんたん質問の進み具合で2つの形に分ける

| かんたん質問 | P-10 の動き |
|---|---|
| Step4 まで答えた | 今までどおり、Step1〜4 の回答をもとに AI が深掘り質問（3〜5問）を出す |
| まだ答えていない（Step1 の前・途中） | AI からは質問しない。ユーザーの質問に AI が答え、そのやり取りから希望の傾向を記録する |

- 区切りは「Step4 の画面で次へ進んだか」です。Step4 は任意なので、タグを1つも選ばなくても「答えた」とします。
- ハブの「AIに相談する」は、これまでどおり、どの状態でも押せます（PR #23 のレビュー指摘への対応。P-01 は変えません）。
- 理由：Step1〜4 の回答が無いのに仮の回答（予算300万円など）で質問を作ると、本人の希望と関係ない質問になるためです。

#### 追記：2026-10-20（issue #30 で変更）　P-10 はチャットの自由な相談だけにした

上の表と理由は、決めた時点の記録として残しています。その後、担当の仲村さんが issue #30 で次のように決めました。

| 項目 | 変更後（2026-10-20 決定） |
|---|---|
| P-10 の形 | 質問を並べて、まとめて答える形をやめ、チャット画面1つにした |
| AI からの質問 | しない。かんたん質問の進み具合（Step4 まで答えたか）に関係なく、誰が開いても、利用者の質問に AI が答える自由な相談にした。上の表の「Step4 まで答えた」の行の深掘り質問は取り消した |
| 回答の扱い | Step1〜4 の回答があれば AI への指示に含め、無ければ含めない。仮の回答（予算300万円など）は作らない（上の「仮の回答を作らない」は、この形で実装された） |
| やり取りの保存 | 新しいテーブル `AI_CHAT_MESSAGES` に、発言ごとに保存する |
| `ONBOARDING_ANSWERS.DEEPDIVE_QA` 列 | 列は残すが、アプリからは使わなくなった（消すかどうかは DB の担当と相談します） |
| 希望の傾向の記録 | まだ実装していない（記録先は DB の担当と相談します） |

- 共有 DB への反映：`db/01_create_tables.sql` の末尾に追記した `AI_CHAT_MESSAGES` の部分だけを実行する必要があります（DB の担当に連絡します）。
- 理由（P-10 の担当・仲村さんが決定）：かんたん質問の進み具合で AI の動き（AI が質問する／利用者の質問に答える）が変わると、利用者に分かりにくいためです。そのため、どの状態でも同じ「自由な相談」にそろえました。

未実装・相談事項：
- P-10 の変更（回答が無いときに仮の回答を作らない、相談の形を足す）は、P-10 の担当（仲村さん）と相談します。（2026-10-20 追記：issue #30 で決まり、チャット形式として実装した。上の「追記：2026-10-20（issue #30 で変更）」を参照）
- 「希望の傾向」の記録先（Supabase の列かテーブル）は、DB の担当と相談します。

### 2. 「基本情報とタグを変更」を足す（Step3・Step4 をあとから直せるようにする）

- 日程・予算（Step3）とタグ（Step4）は、見学や家族との話し合いで変わることがあります。そのため、Step4 まで答えたあとでも直せるようにします。Step1・Step2 は、あとから直す対象にしません。
- 新しい画面は作りません。P-08（Step3）と P-09（Step4）を、見直しとして開き直します。入り口の名前は「基本情報とタグを変更」です。
- 直した回答は、T-03 ONBOARDING_ANSWERS の同じ行に上書きします。
- 直したあとの扱いは、進み具合で分けます。

| 直した時点 | 扱い |
|---|---|
| プランを作る前（〜P-10） | 回答を書き換えるだけ。深掘り質問にまだ答えていなければ、質問を作り直す |
| プランを作ったあと、プランナーに送る前（P-12） | 「新しい回答でプランを作り直しますか？」と確認する |
| プランナーに送ったあと（担当を決めている・担当が決まった） | AI では作り直さない。変わった点を担当プランナーに伝える（伝え方は未定。例：チャットに自動で知らせる） |

未実装・相談事項：
- P-08・P-09 の見直しの作りは、画面ができてから作ります。P-01 のハブの入り口（いまの「かんたん質問を見直す」を置き換える）も、そのときに変えます。
- 上書きすると、プラン（T-04 PLANS）の元になった回答も変わります。プランナーに送ったあとの変更の伝え方とあわせて、DB の担当と確認します。
