# ログイン（P-03） 変更内容まとめ

作成日：2026-10-20　（基本設計書 P-01 反映版からの変更点）

ログイン画面（P-03）のハリボテ（見た目と画面の動き）をつくる中で決まった内容と、設計書に無い追加をまとめます。設計書（docx）にはまだ反映していません。仕様変更は最後にまとめて設計書に書き込む方針のため、ここに記録しておきます。

## 設計書どおりに作ったところ（6-2・8-2）

- メールアドレスとパスワードで認証する
- 失敗したときは「メールアドレスまたはパスワードが正しくありません」と出す（どちらが間違っているかは教えない）
- 成功したら、利用者の種別に合わせた画面へ自動で進む（顧客 → トップページ（P-01 のハブ）、プランナー → プランナーダッシュボード（P-15）、管理者 → 管理者ダッシュボード（P-18））
- 「パスワードを忘れた方はこちら」のリンクから、パスワードリセット申請（P-04）へ進む

## 設計書からの変更点

| 項目 | 設計書（P-01 反映版） | 変更後 |
|---|---|---|
| ログインした顧客の行き先（5-2 の流れ） | ログイン（P-03） → Step1（P-06） | ログイン（P-03） → ログイン後のトップページ（P-01 のハブ）。ハブの「次にやること」から Step1 へ進む（P-01 反映版の「確認してほしい点」にあった行き先を、P-01 に決めた） |

## 設計書に無い追加（P-03 の画面）

- 「はじめての方は 会員登録」のリンク（会員登録（P-02）の「すでに会員の方は ログイン」と対にする）
- パスワード欄の「表示／隠す」の切り替え（P-02 と同じ部品）
- 未入力のときは、各項目のすぐ下に「〇〇を入力してください」を出す
- 画面の左側に「はじめての方へ」として、登録するとできること（P-02 と同じ3つ）と［会員登録してはじめる］を出す

## P-03 の画面の詳細（実装に合わせた補足）

ハリボテ（`bridal-app` の `auth/controller/LoginController.java`・`auth/dto/LoginForm.java`・`auth/service/LoginService.java`・`templates/auth/login.html`、P-02 と共通の `templates/common/auth-merit.html`・`css/auth.css`・`js/auth.js`）で作った内容は次のとおりです。

### 画面構成（PC 基準・2列。P-02 と同じ骨格）

| 列 | 内容 |
|---|---|
| 左 | はじめての方へ：登録すると、できること（3つ）／［会員登録してはじめる］ |
| 右 | ログインのフォーム（メールアドレス・パスワード）、パスワードを忘れた方はこちら、［ログイン］ボタン、会員登録へのリンク |

タブレット・スマホでは1列にして、フォームを先に、説明を後に並べます。

### ハリボテ用の仮の仕組み

- DB の代わりに、次の仮のアカウントと照らし合わせます。パスワードは3つとも `abc12345` です。

| メールアドレス | 種別 | ログイン後の行き先 |
|---|---|---|
| `test@example.com` | 顧客（テスト 顧客） | ハブ（仮の URL `/after-login-tmp`） |
| `planner@example.com` | プランナー（テスト プランナー） | P-15（仮の URL `/planner/dashboard`。画面がまだ無いので、いまは 404） |
| `admin@example.com` | 管理者（テスト 管理者） | P-18（仮の URL `/admin/dashboard`。画面がまだ無いので、いまは 404） |

- 本当のログイン（セッションへの保存）はしていません。ハブのヘッダーには、ログインした直後だけ、その人の名前を「〇〇 様」と出します。
- パスワードリセット申請（P-04）はまだ無いので、リンクは仮の URL `/auth/password-reset` です（いまは 404）。
- 30分操作が無いときの自動ログアウト（8-2）は、本当のログイン機能を作るときに入れます。

## レビュアー・チームに確認してほしい点

- 本当のログイン機能（Spring Security）：USERS の EMAIL と BCrypt のハッシュで確かめる形に置き換え、30分の自動ログアウトも入れてください（`LoginService.java`・`LoginController.java` に TODO を残しています）。会員登録（P-02）の「登録と同時にログインさせる」処理とあわせて進めると、つながりが自然です。
- プランナーダッシュボード（P-15）・管理者ダッシュボード（P-18）の URL：決まったら `LoginController.java` の定数を合わせてください。
