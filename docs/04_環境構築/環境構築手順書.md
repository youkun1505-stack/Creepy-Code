# 環境構築手順書

AIブライダルプランニング支援システム（P2C：Creepy Code）

作成日：2026-10-07　改訂日：2026-10-14（データベースを Oracle から Supabase に、AI を Gemini API から Sign in with ChatGPT に変更）

この手順書のとおりに進めると、自分の PC（Windows）でアプリ `bridal-app` を起動できるようになります。
手順だけをざっと知りたいときは、簡単版の [Pullしたらやること.md](Pullしたらやること.md) を見てください。

---

## 1. 前提（先に用意するもの）

| もの | 何に使うか |
|---|---|
| Pleiades 2023-12（Eclipse） | プログラムを書いて、アプリを起動する |
| SourceTree | Git（ファイルの変更履歴を管理するしくみ）を画面で操作する |
| DB の接続情報（3つ） | アプリがデータベースにつなぐための値。**管理担当から受け取る**（手順4） |
| インターネット接続 | データベースがインターネット上（Supabase）にあるため、起動のたびに必要 |

> 以前の手順で使っていた Docker Desktop・Oracle のコンテナ・SQL Developer は、このプロジェクトでは**使わなくなりました**（授業では引き続き使います）。

## 2. リポジトリをクローンする

リポジトリ（チームのファイル置き場）を、自分の PC にコピー（クローン）します。

1. SourceTree を開き、「Clone」を押す。
2. 元のパスに GitHub の Creepy-Code の URL を入れる。
3. 保存先のパスを **`C:\pleiades\2023-12\workspace\Creepy-Code`** にする。
4. 「クローン」を押す。

> **OneDrive の中には置かないでください。** OneDrive が自動で同期するときにファイルをロック（使用中にする）するため、ビルドや Git の操作が失敗することがあります。

---

## 3. データベースのしくみ（読むだけ）

データベースは **Supabase**（インターネット上で PostgreSQL というデータベースを貸してくれるサービス）を使います。チーム6人で**1つのプロジェクトを共有**します。

- 自分の PC にデータベースを入れる必要はありません。
- **全員が同じデータを見ています。** 自分が登録・変更・削除したデータは、ほかのメンバーの画面にもすぐ反映されます。
- テーブルは `creepy` というスキーマ（テーブルを入れる箱）に入っています。
- スキーマやテーブルを作る SQL（`db/` の中）は、**管理担当が1回だけ実行します。各自では実行しません。**

---

## 4. DB の接続情報を環境変数に設定する

接続情報は、リポジトリのファイルには書かず、自分の PC の「環境変数」に設定します。

1. 管理担当から、次の3つの値を受け取る。
2. Windows のスタートメニューで「環境変数」と検索し、「環境変数を編集」を開く。
3. 上の「ユーザー環境変数」の「新規」から、次の3つを追加する。

   | 変数名 | 値 |
   |---|---|
   | `DB_URL` | `jdbc:postgresql://` で始まる接続先 |
   | `DB_USERNAME` | `postgres.` で始まるユーザー名 |
   | `DB_PASSWORD` | データベースのパスワード |

4. **Eclipse を開いている場合は再起動する**（再起動しないと、新しい環境変数が読み込まれません）。

> **接続情報は、リポジトリのファイル・GitHub の Issue やコメント・公開の場所には絶対に書かないでください。** このリポジトリはだれでも見られる公開リポジトリです。パスワードが漏れると、データベースを外から自由に書き換えられてしまいます。
> もし間違ってコミットしてしまったら、すぐに管理担当に伝えてください（パスワードを作り直します）。

## 5. データベースの中身を見る（必要な人だけ）

データの確認は、Supabase の画面（ダッシュボード）で行います。管理担当から招待メールが届いたら、Supabase にログインしてください。

1. Supabase のダッシュボードでプロジェクトを開く。
2. 左のメニューの「Table Editor」を押す。
3. 上のスキーマの選択欄を `public` から **`creepy`** に切り替える。

> テーブルが15個見えれば正しい状態です。

## 6. Eclipse にプロジェクトを読み込む

1. Eclipse（Pleiades 2023-12）を開く。ワークスペースは `C:\pleiades\2023-12\workspace` を選ぶ。
2. メニューの「ファイル → インポート」を押す。
3. 「Maven → 既存 Maven プロジェクト」を選んで「次へ」を押す。
4. 「ルート・ディレクトリー」の「参照」から `C:\pleiades\2023-12\workspace\Creepy-Code\bridal-app` を選ぶ。
5. `/pom.xml` にチェックが入っていることを確認して「完了」を押す。
6. 右下に進み具合が表示され、必要なライブラリ（部品）のダウンロードが始まる。初回は数分かかるので、終わるまで待つ。

---

## 7. アプリを起動する

1. 左の「パッケージ・エクスプローラー」で `bridal-app → src/main/java → com.creepycode → BridalApplication.java` を開く。
2. `BridalApplication.java` を右クリック →「実行 → Spring Boot アプリケーション」を押す。
   （メニューに無い場合は「実行 → Java アプリケーション」でも起動できます）

## 8. 起動できたか確認する

下の「コンソール」に、次の行が出れば完了です。

```
HikariPool-1 - Start completed.
```

これは「データベース（Supabase）への接続に成功した」という意味です。続けて `Started BridalApplication` と出れば、アプリの起動も完了しています。

> ブラウザで http://localhost:8080 を開くと、Spring Security（ログイン機能の部品）の標準のログイン画面が出ます。画面はまだ作っていないので、これで問題ありません。

止めるときは、コンソールの右上の赤い四角（終了）を押します。

## 9. AI を使うとき（Sign in with ChatGPT）

初期状態では、AI は固定の文章を返す「ダミーモード」で動きます。**ふだんの開発はダミーモードのままで進めます。この章の作業は、本物の AI を動かす PC でだけ行います。**

本物の AI は、**Sign in with ChatGPT**（ChatGPT のアカウントでサインインし、その人の ChatGPT のプランの利用枠で AI を呼ぶしくみ）を使います。API キーは使いません。

- サインインには、ChatGPT の **Plus または Pro** のプランが必要です。チームでは**仲村のアカウント**を使います。
- 使った分は、サインインした人の利用枠から引かれます。画面の利用者（顧客・プランナー）ごとではありません。
- Java から直接は使えないため、Node.js で作った中継プログラム（`ai-relay` フォルダ）を bridal-app の横で動かします。

### 9-1. 準備（最初の1回だけ）

Node.js 22.12 以上が入っていることを確認してから、`ai-relay` フォルダでコマンドを実行します。

1. `npm run setup` を実行する（OpenAI の部品を取得してビルドする。数分かかる）。
2. `npm run sign-in` を実行する。ブラウザが開くので、ChatGPT にサインインし、プランの利用を許可する。
3. 「サインイン済みです。AI を使えます。」と表示されれば完了。

### 9-2. 本物の AI で動かす

1. `ai-relay` フォルダで `npm start` を実行する（中継プログラムが起動する。この画面は開いたままにする）。
2. Windows の環境変数 `APP_AI_MODE` に `chatgpt` を設定し、Eclipse を再起動する（設定のしかたは手順4と同じ）。
3. bridal-app を起動する。

> 今、本物の AI を使う画面は **AI深掘り質問（P-10、`http://localhost:8080/hearing/deepdive`）** だけです。ログイン機能は別の担当が作成中のため、今はログインなしで開けます。この画面では、テストユーザーの顧客（USER_ID = 1）の回答として保存されます。
> 中継プログラムが動いていないと、画面に「時間がかかっています」と表示されます。

ダミーモードに戻すときは、`APP_AI_MODE` を `dummy` にする（または削除する）して、Eclipse を再起動します。

### 9-3. 守ること

- サインインの情報は、リポジトリの外（`C:\Users\<ユーザー名>\.creepy-code`）に保存されます。**リポジトリには絶対に入れないでください。**
- AI に送る内容は、**架空のテストデータだけ**にしてください。実在の人の個人情報は送らないでください。
- 以前の手順で設定した環境変数 `GEMINI_API_KEY` は使わなくなったので、削除してかまいません。`APP_AI_MODE` を `api` にしていた人は、`dummy` に戻すか削除してください。

くわしくは [ai-relay/README.md](../../ai-relay/README.md) を見てください。

## 10. `db/` の SQL について

共有の Supabase（プロジェクト名：Creepy Code Tamaura）には、2026-10-14 に次の SQL を実行済みです。**メンバーは実行する必要はありません。**

| ファイル | 内容 | 状態 |
|---|---|---|
| `db/00_create_schema.sql` | `creepy` スキーマを作る | 実行済み |
| `db/01_create_tables.sql` | テーブル15個を作る | 実行済み |
| `db/02_insert_master.sql` | マスタの仮データ（アーキタイプ3件・料金5件） | 実行済み |
| `db/03_insert_testdata.sql` | テストユーザー3人（顧客・プランナー・管理者） | 実行済み |
| `db/保留/99_drop_tables.sql` | 全テーブル削除 | **ふだんは実行しない** |

テストユーザーのメールアドレスとパスワードは、`db/03_insert_testdata.sql` の先頭に書いてあります。
データベースは全員で共有しているので、SQL の実行は**管理担当だけ**が行います。特に `99_drop_tables.sql` は全員のデータが消えます。

## 11. 管理担当がやること（チームで1回だけ）

Supabase のプロジェクトを用意して、接続情報をメンバーに配ります。

1. https://supabase.com でアカウントを作り、新しいプロジェクトを作る。
   - リージョン（サーバーの場所）は日本に近い場所（Tokyo など）を選ぶ。
   - 「Database Password」は自動生成のものを使い、控えておく。これが `DB_PASSWORD` になる。
2. 左のメニューの「SQL Editor」を開き、`db/00_create_schema.sql` から `db/03_insert_testdata.sql` までを番号順に貼り付けて「Run」を押す（2026-10-14 に実行済み）。
3. 画面上部の「Connect」を押し、**「Session pooler」**の接続情報（Host・Port・User）を確認する。
   - 「Direct connection」や「Transaction pooler」ではなく、「Session pooler」を使う。学校や自宅の回線（IPv4）からでもつながり、このアプリの作りに合っているため。
4. 次の形で、メンバーに配る3つの値を作る。

   | 変数名 | 値の作り方 |
   |---|---|
   | `DB_URL` | `jdbc:postgresql://<Host>:5432/postgres?sslmode=require` |
   | `DB_USERNAME` | 「User」の値（`postgres.<プロジェクトID>` の形） |
   | `DB_PASSWORD` | 手順1で控えたパスワード |

5. 3つの値を、**チームのメンバーだけが見られる場所**（非公開のチャットなど）でメンバーに伝える。GitHub には書かない。
6. プロジェクトの設定の「Team」から、メンバーを招待する（データの中身を見られるようにするため）。

> パスワードが漏れた・漏れたかもしれないときは、Supabase の「Database」の設定からパスワードを作り直し、新しい値を全員に配り直します。

## 12. よくあるトラブル

| 症状 | 原因 | 対処 |
|---|---|---|
| `Could not resolve placeholder 'DB_URL'`（`DB_USERNAME`・`DB_PASSWORD` の場合もある） | 環境変数が設定されていない／設定したあと Eclipse を再起動していない | 手順4を確認し、Eclipse を再起動する |
| `password authentication failed` | パスワードの間違い | `DB_PASSWORD` の値を確認する。前後に空白が入っていないかも見る |
| `Tenant or user not found` | ユーザー名または接続先の間違い | `DB_USERNAME` が `postgres.<プロジェクトID>` の形になっているか、`DB_URL` の Host が配られた値と同じか確認する |
| `The connection attempt failed` や `Connection timed out` | インターネットにつながっていない／回線がポート5432を通さない／Supabase のプロジェクトが一時停止している | ネットの接続を確認する。別の回線（テザリングなど）で試す。直らなければ管理担当に伝える |
| `Max client connections reached` など、接続数が多すぎるというエラー | 全員の接続の合計が Supabase の上限を超えた | 使っていないアプリを止める。何度も出るときは管理担当に伝える |
| 昨日までつながっていたのに、全員つながらなくなった | 無料プランは、しばらく使われないとプロジェクトが一時停止する | 管理担当が Supabase のダッシュボードでプロジェクトを再開する |
| `Port 8080 was already in use` | 別のアプリ（授業のアプリなど）が 8080 番を使っている | コンソールの赤い四角で、動いている別のアプリを止めてから起動し直す |
| `UnsupportedClassVersionError` や、Java のバージョンのエラー | Eclipse が Java 17 以外を使っている | `bridal-app` を右クリック →「Maven → プロジェクトの更新」。直らなければ「プロパティ → Java のビルド・パス → ライブラリー」で JRE が 17 になっているか確認する |
| 日本語が文字化けする（Eclipse） | ファイルの文字コードが UTF-8 になっていない | 「ウィンドウ → 設定 → 一般 → ワークスペース」の「テキスト・ファイルのエンコード」を `UTF-8` にする |
| ライブラリのダウンロードが終わらない／赤いエラーが消えない | ダウンロードの途中で失敗した | `bridal-app` を右クリック →「Maven → プロジェクトの更新」で「スナップショット/リリースの強制更新」にチェックを入れて OK |
