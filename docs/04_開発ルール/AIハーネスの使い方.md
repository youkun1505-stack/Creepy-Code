# AIハーネスの使い方

AI に実装を頼むときの決まりごとをまとめた仕組みです。新しいコマンドや追加の道具は使いません。
Claude Code（Claude デスクトップアプリの「Code」や、VS Code などで使う Claude Code）や Codex でこのリポジトリを開くと、
次のファイルが自動で読み込まれ、AI がその決まりどおりに動きます。ファイルの置き場所は、それぞれの公式の説明に合わせています。

| ファイル | 役割 |
| --- | --- |
| `AGENTS.md`（リポジトリ直下） | すべての AI が守るルール。Codex はこれを直接読む |
| `.claude/CLAUDE.md` | Claude Code 用の進め方（`AGENTS.md` を読み込んだうえで、役割の分け方を足したもの） |
| `.claude/agents/implementer.md`・`reviewer.md` | Claude Code の実装役（軽いモデル）とレビュー役（賢いモデル） |
| `.claude/settings.json` | Claude Code にさせない操作（取り込みなど）、毎回確認する操作、フック |
| `.codex/agents/implementer.toml`・`reviewer.toml` | Codex の実装役（軽いモデル）とレビュー役（賢いモデル） |
| `.codex/rules/git.rules` | Codex にさせない操作、毎回確認する操作 |
| `.codex/hooks.json` | Codex のフック（Git のフックを有効にする、main・develop の上でのファイル変更を止める） |
| `.githooks/` | Git のフック。人が操作しても AI が操作しても、Git のルールに合わないコミット・送信を止める |

## 仕組み

1. メインの会話の AI が「司会役」になり、あなたと一緒に作業メモ（目的・機能ごとの受け入れ条件・変更してよい範囲）を作ります。
2. 機能ごとに、実装役が作り、別の記憶を持つレビュー役が確かめます。レビュー役の指摘は「チケット」という一時ファイルで実装役に渡され、機能が終わると削除されます。
3. 重い指摘がなくなるまで「直す → 確かめる」を自動で繰り返します（1機能で3回まで。超えたら相談されます）。
4. 終わった機能から、作業ブランチにコミットされます。GitHub への送信と PR 作成は、あなたが「はい」と言ったときだけです。

## 頼み方の例

| やりたいこと | 話しかける例 |
| --- | --- |
| 新しい作業を始める | 「issue #12 のプラン提案画面を作りたい。作業メモから一緒に作って」 |
| 作業メモで進める | 「この作業メモで進めて」 |
| 様子を聞く | 「いまどこまで進んだ？」 |
| 今日の作業を終える | 「今日はここまで」 → 次にやることを聞かれるので答える |
| 別の人の続きをする | 「feature/12-plan-view の続きをやる」 |
| GitHub に送る | 「送って PR を作って」 → 内容を確認して「はい」 |
| PR が develop と衝突した | 「最新の develop を取り込んで」 → 衝突した内容を見て、どちらを残すか答える |

## AI がしないこと

- `main`・`develop` への直接の送信、強制送信、付け替え（rebase）、`reset --hard`、ブランチの削除、PR の取り込み
- 取り込み（merge）は、自分の作業ブランチに最新の `develop` を取り込むときだけ行います。
  そのときも必ずあなたに確認し、衝突したら両方の内容を見せて、どう残すかをあなたに決めてもらいます。
- `main`・`develop` の上でのファイル変更やコミット（作業の前に必ずブランチを確認します）
- 作業メモの「変更してよい範囲」の外の変更
- API キーなどの秘密情報を書くこと、`AGENTS.md`・`.claude/`・`.codex/` の変更（リーダーに頼まれたときを除く）

## 作業の記録の置き場所

作業メモ（`task.md`）・チケット（`T-1.md` など）・引き継ぎ記録（`handoff.md`）は、作業のあいだだけ使う一時ファイルです。
自分の PC の `.ai-tmp/<ブランチ名の / を - にした名前>/` に置かれ、Git では共有されません。リポジトリには残りません。

- チケットは、機能を締めるときと、その日の作業を終えるときに削除されます。
- 作業メモと引き継ぎ記録は、PR を作ったあとに削除されます。
- 別のメンバーに続きを頼むときは、「今日はここまで」のときに AI が表示する引き継ぎの内容を相手に渡してください。
  続きをする人は、その内容を AI に貼り付けて「〇〇ブランチの続きをやる」と伝えます。

## Git のフック（自動の見張り）

`.githooks/` のフックが、コミットと送信の直前に自動で確かめます。人が SourceTree で操作したときも同じように止まります。

| 止めるもの | 表示される理由の例 |
| --- | --- |
| `main` へのコミット | いまのブランチは「main」です。main には直接コミットできません |
| feature/・fix/・docs/ で始まらないブランチの送信 | feature/〇〇・fix/〇〇・docs/〇〇 の形にしてください |
| `main`・`develop` への送信 | 作業ブランチを送信して、develop 向けの PR を作ってください |
| 強制送信・GitHub のブランチ削除 | 強制送信はしない決まりです |

Claude Code・Codex でこのリポジトリを開くと、フックは自動で有効になります。
Codex では、最初に「このプロジェクトを信頼する」を選び、`/hooks` でフックの内容を確認して許可してください
（信頼しないと `.codex/` の設定が読み込まれません）。AI を使わずに SourceTree だけで
作業する人は、一度だけリーダーに有効にしてもらってください（`git config core.hooksPath .githooks`）。

## リーダーにお願いしたいこと

AI への決まりは、すべての書き方を防げるわけではありません。確実に止めるため、GitHub の設定で
`main` と `develop` を保護し（直接の送信を禁止し、PR を必須にする）、取り込みは人が行う運用にしてください。
